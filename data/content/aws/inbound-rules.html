O par ec2-rds-4 / rds-ec2-4

Esses dois foram criados pelo assistente "Connect to RDS" e implementam o padrão correto de security group como identidade:

  • ec2-rds-4 não tem nenhuma regra de entrada. Ele existe só para ser anexado às EC2 que podem falar com o banco — é um crachá.
  • rds-ec2-4 libera 3306 com origem ec2-rds-4, não com CIDR.

Consequência prática: para dar acesso ao banco a uma EC2 nova, anexe ec2-rds-4 a ela — não adicione IP em lugar nenhum. Instância que troca de IP continua funcionando. As descrições da AWS nesses grupos avisam: "Modification could lead to connection loss".

Hoje carregam o crachá: legado-main, legado-slave, api-main, cron, boomia. socket, centralizador, papa-entulho e kong não têm acesso ao RDS principal — o que é intencional e vale saber antes de tentar apontar um serviço novo para o banco.

É aqui que se libera IP novo para conectar no banco de produção pelo DBGate/cliente MySQL. Sempre com /32 e sempre com descrição — sem ela, ninguém consegue saber depois de quem é a regra nem quando pode remover. Ver também IP White List.

As 4 instâncias RDS (boomsistemas db.t4g.xlarge + réplicas replica-1, replica-2, replica-for-dev, todas db.t4g.small) usam esse grupo e o rds-ec2-4. Todas estão com PubliclyAccessible: true — ou seja, o único controle de acesso ao banco é essa lista de 7 IPs. Remover uma regra daqui por engano derruba o acesso do time; adicionar um CIDR largo expõe o banco à internet.

Riscos abertos

1. SSH aberto para o mundo em 9 grupos

tcp/22 :: 0.0.0.0/0 está em launch-wizard-1 a -8, em redis-legado e em kong-and-to-loadbalance — praticamente toda a frota. O acesso depende exclusivamente da chave privada (~/keys/new-prod-sp.pem e afins). Restringir para os IPs do escritório/VPN é a mudança de maior impacto e menor esforço nessa conta.

2. Banco do Papa Entulho exposto

launch-wizard-4 libera tcp/3308 (MariaDB) para 0.0.0.0/0. É o banco de logs — o mesmo que o legado acessa em boom-papa-entulho.duckdns.org:3308 (ver Services/PapaEntulhoDb.php). Está aberto porque o acesso é feito pela internet pública via DuckDNS, e não por rede interna. Como esse banco guarda mensagens de exceção, stack traces e identificação de usuário (logs_legacy_exceptions), a exposição não é trivial. Substituir o DNS público por SG-a-SG resolveria os dois problemas de uma vez.

3. Porta 3000 do Kong aberta

launch-wizard-2 tem tcp/3000 :: 0.0.0.0/0, enquanto as portas 8401-8402 (GUI) estão corretamente restritas a 4 IPs. Vale confirmar o que responde na 3000 nessa instância e, se não precisar ser público, fechar.

Como consultar sem abrir o console

export AWS_PROFILE=claude-ro

# quem usa qual grupo
aws ec2 describe-instances --region sa-east-1 \
  --query 'Reservations[].Instances[].[Tags[?Key==`Name`]|[0].Value,State.Name,join(`,`,SecurityGroups[].GroupName)]' \
  --output text

# regras de um grupo
aws ec2 describe-security-groups --region sa-east-1 \
  --group-ids sg-044518faf56a13082 --output json

# achar todo mundo com SSH aberto
aws ec2 describe-security-groups --region sa-east-1 \
  --filters Name=ip-permission.from-port,Values=22 \
            Name=ip-permission.cidr,Values=0.0.0.0/0 \
  --query 'SecurityGroups[].GroupName' --output text

O profile claude-ro é somente leitura — alteração de regra continua sendo feita no console ou por quem tem credencial de escrita.
