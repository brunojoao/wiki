Integrador de Portais de Veículos — Arquitetura Técnica

Esta página documenta tecnicamente como funciona o módulo de integração com portais de veículos (OLX, iCarros, Webmotors, Mercado Livre, Mobiauto, Boom, etc.) no projeto app.boomsistemas.com.br (Zend Framework 2 / PHP 7.x): arquitetura, arquivos, funções, tabelas, onde se configura e como adicionar um novo portal.

 

1. Visão geral da arquitetura

O integrador não usa Strategy Pattern. A lógica é centralizada em dois grandes if/else em cascata, distribuídos em duas camadas:

Fluxo macro:

[Camada App]                                      [Camada Utils]
VeiculoIntegracaoTable::saveIntegracao()  ──────► Utils\Integracao\Integracao (construtor)
  └─ if/else por integrador (~25 portais)            └─ if/else por $class → Integrador<Portal>()
       └─ geraData<Portal>()  (monta payload)             └─ chama API externa (curl / SOAP / SDK)
       └─ new Integracao($data, $filial, 'class')         └─ getResult() / getError()
       └─ INSERT/UPDATE em sis_veiculo_integracao

3. Tabelas do banco

As tabelas são genéricas — servem para todos os portais. A chave que identifica cada portal é a string integrador_class / integrador_chave (ex: 'olx', 'webmotors', 'boom').

Tabelas de lookup por portal (de-para de marca/modelo/combustível/opcional): sis_olx_marca, sis_olx_modelo, sis_icarros_marca, sis_webmotors_marca, sis_mobiauto_marca, etc. Consumidas pelos respectivos *Table.php.

 

4. Códigos de status

O campo status que trafega em saveIntegracao() controla a operação:

Já em sis_veiculo_integracao.veiculo_integracao_status e na fila sis_veiculo_integracao_check, o estado final é binário (0=removido/inativo, 1=ativo) — a operação delete da fila é convertida em status=0 no ApiController.

6. Onde se configura (credenciais no cadastro do usuário)

O desenvolvedor original "espalhou" as credenciais de portal dentro do cadastro de usuário. Cada portal tem um bloco de campos na view usuario/integracao.phtml, com name no padrão array indexado pela chave do portal:

integrador[<class>]                    -> checkbox liga/desliga a integração
user_integracao[<class>]               -> usuário / ID / token / cód. loja (varia)
user_integracao_pass[<class>]          -> senha / secret
user_integracao_token[<class>]         -> access token (OAuth)
user_integracao_refresh_token[<class>] -> refresh token (OAuth)
user_integracao_token_expires[<class>] -> expiração do token
user_integracao_codigo[<class>]        -> código da loja / revenda
user_integracao_site[<class>]          -> URL do site
user_integracao_cep[<class>]           -> CEP customizado (variantes OLX)
user_integracao_tel[<class>]           -> telefone customizado (variantes OLX)
external_user_id[<class>]              -> ID externo (Mercado Livre)

Persistência: UsuarioController::saveAction() chama IntegracaoUserTable::saveIntegracao($_POST, $user_id). Importante:

  • Apenas admin (grupo_acesso_id == 1) pode salvar integrações.
  • A gravação é "drop & re-insert": deleta todas as integrações do usuário e reinsere a partir do $_POST['integrador'].
  • Se o usuário for desativado (user_status == 0), todas as integrações são apagadas via deleteIntegracoes().
  • Para OLX/iCarros sem token, saveAction() redireciona para o fluxo OAuth (container de sessão guarda retorno, user_id e class).

Leitura na hora do envio: IntegracaoUserTable::getUserIntegracaoVeiculo('<class>', $veiculo_id) devolve as credenciais já casadas com o veículo.

 

7. Rotina pesada de desvinculação (após venda)

Quando um veículo é vendido, o sistema percorre todos os portais ativos do veículo para remover os anúncios. É a operação mais pesada do módulo, e roda de forma assíncrona:

VeiculoController::vendaAction()                         (~linha 745)
   └─ veiculointegracao-table->checkIntegracoes($veiculo_id, 0)   // status 0 = remover
        └─ VeiculoIntegracaoCheckTable::checkIntegracoes()        (~1577-1596)
             ├─ saveCheck(['veiculo_id', 'operacao'=>'delete'])  → INSERT na fila
             └─ sendCheck() → HTTP GET /api/check-integracao/id/boom?veiculo_id=X  (async)
                  └─ ApiController::checarIntegracaoAction()       (~674-712)
                       ├─ sleep(5); ignore_user_abort(true)
                       ├─ clearCheck()
                       ├─ $operacao = (operacao == 'delete' ? 0 : 1)
                       └─ VeiculoIntegracaoTable::processIntegracoes($veiculo_id, 0)  (~1598-1622)
                            └─ foreach (integrações ativas do veículo) {
                                  try { saveIntegracao(status=0) }
                                  catch (Exception $e) { continue }   // não trava os demais
                               }

Ponto crítico: processIntegracoes() é genérico — itera sobre o integrador_class gravado em sis_veiculo_integracao (JOIN com sis_integrador_user). Ou seja, qualquer portal entra automaticamente nesse loop assim que existir o branch correspondente em saveIntegracao() e o veículo tiver registro ativo. O try/catch com continue garante que a falha de um portal não impede a desvinculação dos demais nem trava a venda.

 

8. Camada Utils — execução da chamada externa

O construtor de Utils\Integracao\Integracao recebe ($Data, $filial, $class) e faz outro if/else por $class, delegando para um método privado por portal:

function __construct($Data, $filial, $class) {
    if ($class == 'boom')              $this->IntegradorBoom();        // SOAP
    else if ($class == 'olx')          $this->IntegradorOlx();
    else if ($class == 'mercadolivre') $this->IntegradorMercadoLivre(); // SDK Meli
    else if ($class == 'icarros')      $this->IntegradorIcarros();
    else if ($class == 'webmotors')    $this->IntegradorWebmotors();    // SOAP
    else if ($class == 'chavesnamao')  $this->IntegradorChavesNaMao();
    else if ($class == 'comprecar')    $this->IntegradorComprecar();
    // ... demais portais
}
  • Chaves/segredos vêm de variáveis de ambiente via getenv() (ex: boomveiculos_id, mercadolivre_id, mercadolivre_secret, icarros_id).
  • URLs dos webservices são propriedades privadas da classe (ex: $WebmotorsProdCarro, $ChavesnaMaoProd).
  • callAPI($url, $params, $header, $type, $resposta, $json) é o helper cURL genérico (timeouts via TIMEOUT_MEDIUM, CURLOPT_SSL_VERIFYPEER=false). Portais com formato próprio têm helper dedicado (ex: comprecarAPI()).
  • Resultado e erro são lidos via getResult() / getError() pela camada App.

 

9. Blindagem de erros

O módulo é frágil (muitas APIs externas), então a resiliência se apoia em três mecanismos já presentes:

  • Try/catch + handleException(): cada Integrador<Portal>() envolve a I/O em try/catch e loga via handleException($e, 'utils_integracao_<portal>', false) (o false não relança a exceção).
  • Erro persistido, não propagado: falhas viram texto em sis_veiculo_integracao.veiculo_integracao_erro + status=0, sem quebrar o fluxo principal.
  • Loop tolerante: processIntegracoes() isola cada portal num try/catch { continue }.
  • Timeouts curtos no cURL para não pendurar o request principal.

 

10. Como adicionar um novo portal

Para um portal REST simples (sem tabelas de lookup), o esforço é:

  1. Registrar o portal em sis_integrador (INSERT com integrador_class = 'novoportal', descrição, status e order).
  2. View: adicionar o bloco de campos do portal em usuario/integracao.phtml (campos integrador[novoportal], user_integracao[novoportal], etc.). A persistência em IntegracaoUserTable::saveIntegracao() normalmente já é genérica.
  3. Camada App: adicionar branch else if ($integracao['integrador'] == 'novoportal') em VeiculoIntegracaoTable::saveIntegracao() + método geraDataNovoPortal() que monta o payload (usando getByVeiculoId() e getUserIntegracaoVeiculo()).
  4. Camada Utils: adicionar else if ($class == 'novoportal') no construtor de Integracao + método IntegradorNovoPortal() que faz a chamada HTTP (modelar por IntegradorChavesNaMao() / IntegradorComprecar()).
  5. Desvinculação na venda: nada a fazer — processIntegracoes() já é genérico.
  6. (Opcional) Lookup: se o portal exigir de-para de marca/modelo, criar tabelas sis_novoportal_* + um NovoPortalTable (modelar por MobiautoTable/OlxTable) e registrar a factory em Module.php.

 

⚠️ Padrões obrigatórios: manter a string da integrador_class idêntica em todos os pontos (view, sis_integrador, sis_integrador_user, os 2 if/else). Servidor é PHP 7.x (sem sintaxe 8.0+). Todo bloco de controle deve usar chaves { }.
