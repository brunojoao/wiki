API Fica na porta: 3333 (Informação adicional, mas útil para contexto)

Kong (Proxy) fica na porta: 8400

Configuração do Kong (Admin API) fica na porta: 8401 (A porta 8402 é tipicamente o default do Kong para métricas, mas a porta padrão da Admin API é 8001 ou 8444. O deck está usando 8401 nos seus comandos, então usaremos essa como a Admin API.)

Endpoint de Acesso configurado no Kong: localhost:8400/v1 (Este é um Route e Service que será incluído no backup)

Ferramenta de Backup/Restore: decK

💾 Tutorial: Backup e Restauração da Configuração do Kong Gateway com decK (Declarative Configuration)

O decK é a ferramenta oficial do Kong para gerenciar a configuração de forma declarativa, permitindo exportar o estado atual do Kong para um arquivo YAML (backup) e importar esse arquivo para restaurar ou sincronizar o estado (restore).

⚙️ Pré-requisitos e Configurações Chave

 

Para que os comandos do decK funcionem corretamente, é crucial entender as portas do Kong no contexto do Docker:

Nota: Se você estiver usando um docker-compose ou docker network onde o container kong está acessível por hostname, o kong-addr no seu comando deve ser http://kong:8401. Se o decK não estiver na mesma rede ou estiver rodando diretamente no seu host, você precisará usar http://localhost:8401.

 

1️⃣ Fazendo o Backup (Dump) da Configuração

Este comando irá exportar toda a configuração de entidades do Kong (Services, Routes, Plugins, Consumers, etc.) para um arquivo YAML dentro do container deck.

 

➡️ Comando de Backup

 

docker exec deck deck gateway dump \
  --kong-addr http://kong:8401 \
  --output-file /deck/kong.yaml \
  --yes

 

2️⃣ Validando o Arquivo de Configuração

Antes de restaurar, é uma boa prática validar a sintaxe do arquivo YAML para evitar erros.

Bash

 

docker exec deck deck gateway validate /deck/kong.yaml

 

3️⃣ Restaurando a Configuração (Sync)

Este comando irá ler o arquivo YAML e sincronizar o estado do Kong com o que está definido no arquivo. Ele adiciona, atualiza e remove entidades no Kong para que correspondam exatamente ao arquivo kong.yaml.

 

➡️ Comando de Restauração (Sync)

 

docker exec deck deck gateway sync --kong-addr http://kong:8401 /deck/kong.yaml

 

⚠️ Segurança: Simulação (Diff)

 

Sempre que possível, use o comando diff primeiro. Ele mostrará as alterações que o sync fará antes de aplicá-las.

Bash

 

docker exec deck deck gateway diff --kong-addr http://kong:8401 /deck/kong.yaml

Isso garante que você não delete ou sobrescreva acidentalmente uma configuração importante. Apenas se o diff mostrar as mudanças esperadas, execute o comando sync.
